# 停止实例：核对身份、按进程组发信号、等到真的没了

## 背景

「停止」要回答的只有一个问题：那个实例是不是真的不在跑了。中间有几处会骗人——pid 会被
系统复用；远端实例是 `setsid` 起的独立会话，本机没有它的子进程句柄；而 DSH 自己带 restart
helper，原进程退出后一两秒就会在同一端口起一个替代进程。只对着记下的 pid 发一个信号就报
「已停止」，很可能停错了人，或者留下一个还在答话的实例，几分钟后周期对账又把它放回运行中。

## 决策

**一次停止 = 身份核对 → 发信号 → 确认消失；远端把这三步放进同一个远端 shell 脚本，一次调用
完成。**

1. 身份核对：pid 与启动时记下的进程启动时间（`/proc/<pid>/stat` 第 22 字段）一起比。启动
   时间读不到就不发信号，如实报错并给出在那台机器上停它的命令；启动时间不匹配说明 pid 已被
   复用，按「已退出」处理，不发信号。
2. 发信号：SIGTERM 发给 `setsid` 进程组（pid 就是组 id），组发不出去再退回单 pid。只停组长
   会把它起的子进程留下来——实例自己拉起的工具进程会继续占着端口、占着 pnpm store 的锁。
3. 等消失：等待发生在那个远端 shell 里（一次 ssh 顶一段等待），最多 20 秒；本机与远端都按
   0.1 秒轮询（远端 `sleep 0.1`，本机 100 次 × 100 毫秒）。粒度取 0.1 秒是因为 DSH 收到 SIGTERM
   通常一秒内就退，按整秒等是用户能明显感到的「慢」。
4. 追停替代进程（远端）：确认原进程不在之后，再问一次实例端口；上面若有 DSH 样的进程，核对
   pid 与启动时间后一并停掉。最多两轮——DSH 只起一个替代进程，两轮覆盖「停止撞上 helper 的
   启动」，有上限才不会让一个重启循环把这次点击卡住。读不到启动时间的不发信号，报错并给出
   命令。
5. 所有被停的 pid 一起交给注销：只有当前运行表里的进程属于这次停的集合（原 pid 或追停到的替
   代进程）才注销条目；否则说明 DSH 在停止过程中又换了进程，报「被 DSH 重启了，请再点一次停
   止」，不谎称已停止。
6. 只有确认进程真的没了才报「已停止」；机器问不到是「主机不可达」，不是「已停止」（ADR-0007
   的后果）。本机的子进程由等待它退出的任务结束并等注册表清空，被收养的外部进程按 pid 发
   SIGTERM 后同样 0.1 秒轮询。

## 后果

- 停止多一轮端口探测、可能多停一个进程；换来的是「已停止」这三个字有依据。
- 停止期间 DSH 若还在重启自己，页面给的是「被 DSH 重启了，请再点一次停止」，不是一个假的已停止。
- 远端停止是一个脚本，不能拆成「查进程 / 发信号 / 等」三次调用：每次调用都可能重新起一次
  登录 shell（`.bashrc` 载 conda 的机器上一次一秒），而且中间的答案描述的都是已经过去的时
  刻，身份核对与信号之间就留出了 pid 被复用的窗口。
- 本机没有「追停替代进程」这一轮：意外退出走收养（ADR-0007），停止时留下的替代进程由下一次
  启动前的端口预检认领。本机误杀代价可接受、远端不可撤销，所以核对与命令提示只在远端做足。
- ADR-0007 §4 已按实现改写为按进程组发信号并指向本条；本条记停止的完整语义：身份核对、进程组、0.1 秒轮询与追停替代进程。

## 备选方案

- **只停记下的 pid**：被否，见背景（替代进程与 pid 复用两条都会让页面说谎）。
- **拆成三次远端调用，每次单独核对**：被否，见后果。
- **停止时按端口杀**：被否。端口只能证明「有人在听」，说不出它是不是这个实例；核对 pid 与
  启动时间才是。
