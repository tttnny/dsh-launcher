# 远端命令：一条单引号规则、标记信封、base64 字节通道

## 背景

远端的一切都是「用 ssh 在那边跑一段 shell」。这条路上有两个坑：一个词要过两层 shell——本机
ssh 把 argv 用空格拼成一句命令，远端的登录 shell 再拆一次；远端 shell 还会自己打印东西
（`~/.bashrc` 的 banner、版本提示、`bash -i` 的 no job control），整段 stdout 不能当答案。
每个调用点自己拼一遍字符串，就会各错各的。

## 决策

**shell 文本只由 `remote` 模块生成，回答只从标记之间读，字节只走 base64。**

1. **每个进入远端命令的字符串都过 `remote::quote`**：POSIX 单引号，内部 `'` 写成 `'\''`。
   外层用单引号转义而不是包一对普通引号，脚本自己给路径加的引号（路径里可能还有单引号）才
   不会被提前结束。两层都是普通 shell，一条规则同时管住两层；`ssh::script_command` 照它把
   整段脚本变成 `bash -c '…'` / `bash -ilc '…'` 里的一个词。
2. **回答走标记信封**：脚本只把结果放在 `<<<DSH-JSON>>>` 与 `<<<DSH-END>>>` 之间，
   `remote::parse_marked` 只读这一段。取不到标记、JSON 解析不了，都算「远端命令失败」，用
   stderr 尾部说明原因；退出码非 0 时带上退出码。
3. **值由 `dsh_esc` 转义**：删掉控制字符、转义反斜杠与双引号，脚本用 printf 拼 JSON 时不会
   被 banner 里的引号把答案拆坏。
4. **字节一律 base64**：文件读写、日志尾巴、版本 manifest 都走这条文本通道（`base64 < path |
   tr -d '\n'`，写回 `base64 -d`）。ssh 通道是文本，字节必须原样到达；代价是内存里多一层
   编码。
5. **给用户复制的命令再包一层双引号**：`remote::ssh_command` 拼的是
   `ssh <目标> '<bash -ilc "<配方>">'`，配方里因此不能出现双引号——出现了内层引号会提前
   结束（安装配方有测试逐条断言这一点）。终端会话用 `ssh -t <目标> '<脚本>'`，脚本内部的
   每个值各自 quote，靠第二层 shell 还原。

## 后果

- 新增脚本或参数的第一件事是 quote；直接拼字符串的脚本不要写。
- 新脚本必须带标记，标记之间只放 JSON；日志与二进制放在 base64 字段里。
- 等待型脚本的时间预算单独给（`RemoteCall::within(budget_for(wait_secs))`）：调用超时要
  读成「没听到回音」，不是「操作失败」——把两者混在一起，曾经丢掉一个刚装完的版本。
- 用户可复制的 ssh 命令与终端命令行受同一条约束：加双引号会静默改变解析结果。
- 两层 shell 的规则只有一份：启动器自己跑、用户粘贴执行，形状相同。

## 备选方案

- **外层包一对普通引号**：被否。脚本自己带的引号会被提前结束，凭 `ssh_command` 的注释与测试。
- **把整段脚本 base64 后再交给 ssh**：没采用。脚本要能给人看、给人复制，出问题时命令本身与
  stderr 都是线索；而这个办法只省掉外层那一层，远端的值与 JSON 仍然要转义。

## 追加（2026-11 注释清理）

- 给用户复制的目录命令里，路径开头的 ~ 是唯一留在引号外的值：整段 quote 会让登录 shell 不再展开它，所以 ~ 与 ~/ 开头的路径拆成「引号外的 ~」与「照常 quote 的其余部分」两段。
- 远端每次往返都要起一次登录 shell，所以一次启动要问的那几个文件（版本入口、profile 清单、bundle 与 profile 的几份文档）合并成一次读；实例的环境变量随 argv 走 /usr/bin/env 的 KEY=VALUE，不拼 shell 前缀——前缀要多过一层引号规则，而 argv 里每个值已经是独立参数。
- 每条远端命令声明它需要的 shell：只有要按名字找工具（PATH 里的 node、pnpm、git，以及装版本这类配方）的脚本用交互式登录 shell（bash -ilc，读得到 ~/.bashrc 里配的 conda、nvm、Linuxbrew），其余默认非交互 bash -c——一次启动会发十几条脚本，每条都交互式会白等一秒。ssh 自己的参数层还有一条：-o 的值会被 ssh 再按配置文件行解析一遍，含空格的值（macOS 上启动器数据目录的路径就带空格）必须加引号。
- 远端安装的每一步、每一轮各自写一份日志文件（例如 install-<任务>-npm-<轮>.log）：包装脚本只往给它的文件追加，复用同一份会让跟随者从开头读到上一轮的退出标记，把这一轮还没开始的命令当成已完成。退出标记由刚退出的那个 shell 写出，可能比进程本身晚一步：进程已经不在时再读一次日志、不等，读到什么算什么，缺标记就是「被杀」而不是「已完成」。
