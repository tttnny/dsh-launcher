# 用 macOS 原生红绿灯，侧栏开关进主工具栏

## 背景

窗口用 `titleBarStyle: Overlay` + `hiddenTitle`，红绿灯叠在内容之上。早先的实现
（commit `ecc3233`）把原生三颗按钮用 AppKit `setHidden` 藏起来，在侧栏顶部自绘
一组，理由是「想让红绿灯和侧栏控件同线」。为此写了 `traffic.rs`：隐藏按钮、监听
`Resized` 反复重隐，网页侧再用 SVG 画圆、写 hover 显隐与失焦变灰。

代价是持续维护一套仿真件，而且永远差一点：自绘圆的直径、间距、悬停图标、失焦
灰阶都得逐条对齐 AppKit，系统一改观感就脱节。更深的问题在交互——原生按钮的点击
区由 AppKit 拥有，自绘的没有；反过来，把原生按钮抬高（`trafficLightPosition`）
会让标题栏的命中区一起变高，反而吞掉下方真实点击，这正是当初选择隐藏的起因。

## 决策

**1. 恢复原生红绿灯，用 `trafficLightPosition` 定位。**

`tauri.conf.json` 的 `app.windows[0].trafficLightPosition = { x: 20, y: 28 }`
（`windows.rs` 重建窗口时同值）。y 取 28 让三颗按钮在 52px 高的顶部条里垂直居中，
与页面标题、工具栏按钮同一水平线；AppKit 自己管理直径、间距、悬停图标、失焦灰阶。

**2. 侧栏开关移到主工具栏左侧，不再放在侧栏里。**

Finder、Mail、Notes 都是这个布局：红绿灯独占侧栏顶部，侧栏开关在内容工具栏。
这消掉了「开关要和红绿灯抢侧栏顶部那点水平空间」的根本冲突——侧栏收起后只剩
84px 宽，任何放在侧栏里的控件都会挤到绿点上。开关图标是窗口框 + 侧栏轨（展开时
轨道填充），收起/展开都读得懂。

**3. 删除 `traffic.rs`，前端删除自绘红绿灯。**

隐藏原生按钮这件事整体不再需要，连同它的 `Resized` 重隐钩子一起删掉；前端删掉
`.traffic-lights`、`.tl*`、`winFocused` 与 `focus`/`blur` 监听。窗口缩放行为只剩
双击顶部条（`toggleWindowZoom`），关闭/最小化/缩放交回系统。

## 后果

- 红绿灯不再是「像原生」，就是原生：全屏、失焦、辅助功能、悬停图标全部跟随系统。
- 顶栏左侧在 Tauri 下留出红绿灯占位（收起侧栏时 84px 必须容下它们的右缘，约
  79px），展开时侧栏顶部本就是空白拖拽条。
- 命中区回到系统默认：顶部条仍是 `-webkit-app-region: drag` 的可拖拽区，工具栏
  按钮在 `data-no-drag` 下正常可点，不需要再和抬高过的标题栏抢点击。
- 删掉一个平台专用模块（objc2 的 `standardWindowButton` 调用），少一处随 macOS
  版本漂移的仿真代码。

## 备选方案

- **保留自绘、只把颜色/尺寸调准**：被否。仿真件的维护成本恒在，且原生按钮的点击
  区无法用 SVG 复制，最终仍是「看起来像、点起来不一样」。
- **藏原生按钮但把侧栏开关留在侧栏**：被否。84px 的收起宽度容不下开关与三颗灯
  共存，这是空间上的硬约束，不是像素微调能解的。
- **不用 Overlay，用系统标题栏**：被否。会丢掉工具栏与内容一体化的观感，且现有
  布局（侧栏贯穿全高）依赖 `FullSizeContentView`。
