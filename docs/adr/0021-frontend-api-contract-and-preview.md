# 界面只经 api 层发命令，浏览器预览照同一份契约实现

## 背景

同一份界面跑在两个地方：Tauri 桌面壳里后端是 Rust 命令，`pnpm dev` 在浏览器里打开时
没有后端。命令的调用点因此只能有一处，否则新加或改名一个命令要改三处，漏一处预览就静默
坏掉。

真正难查的是参数键名。Tauri 按命令自己声明的名字查参数：`rename_all = "snake_case"`
的命令读 `host_id`，其余读 camelCase。查不到**不报错**——一个 `Option<T>` 参数读成
`None`，于是「在远程主机上装版本」落到了本机（`start_install_version_task` 就是这样）。
如果浏览器预览接受两种拼写，它会把这类 IPC 错误一直遮住。

## 决策

**视图只经 api 层发命令；浏览器预览实现同一份命令与参数契约；生产构建里没有预览后端。**

1. `src/api/index.ts` 的 `api` 对象是唯一的命令出口。视图与 store 不直接 `invoke`：
   `invoke` 只在 `src/api/tauri.ts` 的 `call` 里出现一次，传输在这里选——桌面走
   Tauri，浏览器走 mock。窗口拖动、系统文件选择器这类桌面外壳的能力直接用 Tauri 的
   窗口/对话框 API：它们不是启动器的后端命令，也没有 mock 对应物。
2. 浏览器预览不是另一套接口：mock 实现同一个命令名、同一份参数键名。哪些命令读
   snake_case 由后端决定，mock 里有一份清单（`SNAKE_CASE_COMMANDS`）和一个按命令取键
   的 `argOf`；它**只**读该命令真读的那个键，不接受另一种拼写。
3. 生产构建剔除 mock：mock 只在 `import.meta.env.DEV` 下动态 import，生产构建里那个
   分支与模块一起被 Vite 去掉；非开发模式发命令直接报「浏览器预览仅在开发模式可用」。

## 后果

- 新增或改名一个命令，要同步三处：Rust 命令声明（它决定键名规则）、api 层、mock 分支。
  mock 的 `default` 分支对未知命令直接抛错，漏实现会在预览里立刻暴露。
- 事件的桥接同形：桌面用 `listen`，预览用内存订阅，入口都在 api 层
  （`onInstanceStatus` / `onTaskProgress` / `onTaskLog`）。
- 预览里的数据是 localStorage 里的一份假数据，不读本机磁盘、不起进程：它证明界面能跑，
  不证明后端行为。
- 键名规则由后端定，mock 只是抄一份「它看不见的规则」。后端改 `rename_all` 时那份清单
  要跟着改，否则预览按错误的键读到 `None`——与真机同一种错法，这是故意的。

## 备选方案

- **预览另写一套调用**：被否。两套契约必然漂移，漂移出来的错要么只在浏览器里出现，要么
  只在桌面里出现。
- **mock 同时接受两种拼写**：被否。它挡住的正是「参数没送到、后端读成默认值」这类错，
  而那是最难在界面上看出来的错。
- **预览也起一个真后端**：被否。浏览器预览的用处就是改界面不用编译 Rust，为此拉起后端
  就把这条好处去掉了。
