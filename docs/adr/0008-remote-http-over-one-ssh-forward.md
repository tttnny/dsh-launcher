# 远程的 HTTP 走同一个主机的 ssh 端口转发

## 背景

远程实例的 DSH 绑在它那台机器上，本机够不着。要够着的是两件事：插件管理（现有客户端是
HTTP + `?token=`，向实例自己的插件管理接口发 JSON-RPC，鉴权 cookie 按请求的 authority 算）
和「打开实例」（契约就是交给系统浏览器打开实例 URL，见 ADR-0002、ADR-0004）。把远端端口
暴露到公网是另一条路，但那要求用户改绑定地址、配反向代理、开防火墙，还要把带 token 的 URL
放到网络上——启动器本来只想管 DSH，不想把它暴露出去。

## 决策

**每个远程主机一条 ssh 端口转发，本机浏览器与插件客户端都从这条转发走。**

1. 按主机合并成一条转发进程：多个实例共用一条 ssh（复用连接），每个运行中的实例一条
   `-L 127.0.0.1:<本地端口>:<远端 URL 的 host:port>`。本地侧一律只绑回环地址。
   转发目标就是运行记录里那个 URL 的 `host:port`，远端侧原样照搬——不猜 DSH 绑在哪。
2. 本地端口默认取**与远端相同的端口号**：这样界面上的地址就是那台机器上真实存在的地址，
   浏览器地址跨次稳定。该端口在本机被占、或低于 1024（用户态绑不了，而实例的端口由它 profile
   的 lan-bind 决定，钉在 80 也合法）时改用一个本机空闲端口——**一致不是技术必需**：
   DSH 的信任策略对任何回环地址都放行，鉴权 cookie 的名字由请求的 Host 头决定
   （`dsh-client-connection` 的 `requestAudience` → `cookieName`），所以换端口两边仍然对得上。
3. 「打开实例」把 URL 改写成 `http://127.0.0.1:<本地端口>/…`（查询串里的 token 原样带着）
   再交给系统浏览器，所以仍然是一次点击就登录。
4. 隧道在需要时才建：实例就绪时就把它建好（界面要同时说清两个地址，插件页也走这条转发），
   打开实例与进插件页时再确认一遍——连接被 `ControlPersist` 收走时，记住的转发要在用之前
   探一次本机端口，没了就重建。启动器退出时撤掉（每条 `-O cancel`，每台主机再 `-O exit`），
   实例停止时不撤：转发按「主机 + 那台机器上的地址」记，同一个实例重启后用的还是这一条，
   而它只占本机一个回环端口，随启动器一起消失。主机连不上或 ssh 认证失败时如实报错，并把
   远端原始 URL 与可复制的 ssh 命令给出来，而不是静默什么都不发生。
   **这条探针的已知局限**：它只回答「这个本机端口有人在听」，不回答「听着的就是我们那条
   转发」——控制主进程真的没了、而这个端口又恰好被本机别的进程占上时，探针会把那个进程当成
   还活着的转发，把 `127.0.0.1:<本地端口>/?token=…` 交给它。要分清只能去问 ssh 自己
   （对那台主机的控制 socket 跑一次 `ssh -O check`），但那等于给「打开实例 / 进插件页」这条
   常用路径每次都添一个子进程，代价大于它挡下的情形，所以这条局限先记在这里。

## 后果

- 本机端口被占时，界面上的地址与远端地址不同，界面必须把「实例在远端的位置」与「本机可达
  的地址」分开说，别让人以为 DSH 绑在本机。
- 插件页的客户端（`native.rs`）不改协议：它的 URL 来自**进程内的运行表**，而运行表里
  远端实例那一格的 `url` 存的就是本机可达的那个地址。远端那份 `running.json` 存的是
  远端原始地址——它是转发的目标，认领时要照它把转发建起来（ADR-0007 的运行记录与本
  运行表是两个东西，别把它们当成同一份）。
- 隧道断开（网络断、待机、服务器重启）与「DSH 拒绝了这个操作」必须给出不同的原因，否则
  用户会被引去重装插件。

## 备选方案

- **把远端端口暴露到公网**：被否，见背景。
- **一律换一个本地端口**：被否。地址每次都要解释「为什么是这个端口」，而且界面上的 URL
  不再是那台机器上真实存在的地址；留作端口被占时的退路即可。
- **在远端跑一个转发脚本，本机直连它**：被否。等于在远端维护一个跟着启动器升级的组件
  （那条路在别处已经否过一次），而 ssh 自带的端口转发是免费的。
