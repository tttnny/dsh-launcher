# 远程的 HTTP 走同一个主机的 ssh 端口转发

## 背景

远程实例的 DSH 绑在它那台机器上，本机够不着。要够着的是两件事：插件管理（现有客户端是
HTTP + `?token=`，向实例自己的插件管理接口发 JSON-RPC，鉴权 cookie 按请求的 authority 算）
和「打开实例」（契约就是交给系统浏览器打开实例 URL，见 ADR-0002、ADR-0004）。把远端端口
暴露到公网是另一条路，但那要求用户改绑定地址、配反向代理、开防火墙，还要把带 token 的 URL
放到网络上——启动器本来只想管 DSH，不想把它暴露出去。

## 决策

**每个远程主机一条 ssh 端口转发，本机浏览器与插件客户端都从这条转发走。**

1. 按主机合并成一条转发进程：多个实例共用一条 ssh（复用连接），每个运行中的实例一条
   `-L 127.0.0.1:<本地端口>:<远端 URL 的 host:port>`。本地侧一律只绑回环地址——把
   `127.0.0.1:` 显式写进 `-L`，不靠对端的 `GatewayPorts` 配置。转发目标就是运行记录里
   那个 URL 的 `host:port`，远端侧原样照搬——不猜 DSH 绑在哪。
2. 本地端口默认取**与远端相同的端口号**：这样界面上的地址就是那台机器上真实存在的地址，
   浏览器地址跨次稳定。该端口在本机被占、或低于 1024（用户态绑不了，而实例的端口由它 profile
   的 lan-bind 决定，钉在 80 也合法）时改用一个本机空闲端口——**一致不是技术必需**：
   DSH 的信任策略对任何回环地址都放行，鉴权 cookie 的名字由请求的 Host 头决定
   （`dsh-client-connection` 的 `requestAudience` → `cookieName`），所以换端口两边仍然对得上。
3. 「打开实例」把 URL 改写成 `http://127.0.0.1:<本地端口>/…`（查询串里的 token 原样带着）
   再交给系统浏览器，所以仍然是一次点击就登录。
4. 隧道在需要时才建：实例就绪时就把它建好（两个地址一起给到界面，插件页也走这条转发），
   打开实例与进插件页时再确认一遍——连接被 `ControlPersist` 收走时，记住的转发要在用之前
   探一次本机端口，没了就重建。撤的时机分两层：实例停止、运行项注销、实例或主机记录消失时，
   撤掉到它那个远端地址的那一条（`tunnel::withdraw`，`-O cancel`），连接留给同一主机上别的
   转发；启动器退出与删主机时才连连接一起收（每条 `-O cancel`，每台主机再 `-O exit`）。
   转发按「主机 + 那台机器上的地址」记，所以同一个实例重启后由 `process::reachable_url_for` 按
   需重建，本机端口不为一个已经不存在的远端地址占着。主机连不上或 ssh 认证失败时如实报错，
   并把远端原始 URL 与可复制的 ssh 命令给出来，而不是静默什么都不发生——托盘里显式的
   「打开」会弹一个说明框，托盘的**双击**打开失败只记日志并退回显示主窗口。
   **这条探针的已知局限**：它只回答「这个本机端口有人在听」，不回答「听着的就是我们那条
   转发」——控制主进程真的没了、而这个端口又恰好被本机别的进程占上时，探针会把那个进程当成
   还活着的转发，把 `127.0.0.1:<本地端口>/?token=…` 交给它。要分清只能去问 ssh 自己
   （对那台主机的控制 socket 跑一次 `ssh -O check`），但那等于给「打开实例 / 进插件页」这条
   常用路径每次都添一个子进程，代价大于它挡下的情形，所以这条局限先记在这里。

## 后果

- 本机端口被占、或远端端口低于 1024 时，界面上的地址与远端地址不同，界面必须把「实例在
  远端的位置」与「本机可达的地址」分开说，别让人以为 DSH 绑在本机。接口已经带了两个地址
  （`InstanceStatus.remote_url`），但界面目前只渲染本机可达的那个：实例详情与实例行都只有
  `url`，远端位置这一行尚未实现。
- 插件页的客户端（`native.rs`）不改协议：它的 URL 来自**进程内的运行表**，而运行表里
  远端实例那一格的 `url` 存的就是本机可达的那个地址。远端那份 `running.json` 存的是
  远端原始地址——它是转发的目标，认领时要照它把转发建起来（ADR-0007 的运行记录与本
  运行表是两个东西，别把它们当成同一份）。
- 隧道断开（网络断、待机、服务器重启）与「DSH 拒绝了这个操作」必须给出不同的原因，否则
  用户会被引去重装插件。
- 启动器自己那条 ssh 连接的控制 socket 有 86 字节的预算。ssh 不直接绑 `ControlPath`：它先绑
  `<ControlPath>.<16 个随机字符>`，再硬链接到那个名字，所以 104 字节的 Unix socket 地址里留
  给启动器的只有 86（macOS 默认数据目录算出来是 89 字节，ssh 直接拒绝；实测 86 可以、87 报
  `too long for Unix domain socket`）。因此 `ssh::socket_path` 能放进数据目录就放，放不下就退
  到 `$HOME/.dsh-launcher-ssh/`，名字里带上数据目录与 ssh 目标两样东西的哈希——一个 socket
  就是一条 ssh 连接，两份配置不能共用一条。`$TMPDIR` 不行（`/var/folders/…` 一样长），`/tmp`
  不行（别人可以先在那个位置上建 socket）。
- `ssh -O forward` 是发给 master 的请求、不会自己建连接，所以 `SshTransport::open_forward` 先把
  连接带起来。退出时 `tunnel::close_all_blocking` 给每条转发 `-O cancel`、每台主机再 `-O exit`：
  撤掉的只是启动器自己那条连接，用户自己的连接在别的 socket 上，一个字节都不碰。
- 上面那条「只动自己的连接」有个漏洞：ssh 目标是用户可以自由填的字符串，而 `-S`（指定控制
  socket 的选项）就藏在里面。启动器把 `-o ControlPath=…` 放在目标之前，但 ssh 的解析结果仍是
  目标里那个 `-S` 说了算（`ssh -G` 会显示生效的 controlpath 就是它）。于是
  `user@host -S /path` 这样的目标会把启动器的 `-O forward` / `-O cancel` / `-O exit` 送到那个
  socket 上——可能是用户自己的一条连接，隔离的假设不成立。目前的实现没有挡这一手：要堵得先
  把目标里的选项挡住，或者把控制参数排到目标之后。
- 远端实例的运行表条目里 `url` 存本机可达的地址、`RemoteRun.remote_url` 存远端原始位置；写
  这两样的地方只有三个受控入口——实例就绪的 `follow_remote_instance`、认领的
  `adopt_remote_process`、地址丢失后找回的 `repair_remote_address`——都走
  `process::local_address_for`（转发建不起来时它给 `None`：代价是地址，不是实例），写进去的
  永远是这条转发算出来的地址，不是远端原始地址。把远端原始地址直接填进 `url`，会让本机同端口
  的别的服务拿到 token，也会让「打开」与托盘以为实例没就绪。
- 「打开」、托盘与插件页取地址都走 `process::reachable_url_for`：它把那条转发重新确认一遍
  （master 被 `ControlPersist` 收走时转发跟着消失，Mac 睡一觉就够）再返回本机可达的地址，
  本机实例则原样返回自己的 URL。

## 备选方案

- **把远端端口暴露到公网**：被否，见背景。
- **一律换一个本地端口**：被否。地址每次都要解释「为什么是这个端口」，而且界面上的 URL
  不再是那台机器上真实存在的地址；留作端口被占时的退路即可。
- **在远端跑一个转发脚本，本机直连它**：被否。等于在远端维护一个跟着启动器升级的组件
  （那条路在别处已经否过一次），而 ssh 自带的端口转发是免费的。

## 修订（2026-11）

决策 §4 原写「实例停止时不撤转发」，与实现相反：停止确认、运行项注销、实例或主机记录消失
时，启动器会按那台机器上的地址撤掉那一条转发，只把 ssh 连接留给同一主机上别的转发；重启时
按需重建。正文已按实现改写。

按代码核对后一并订正的几处：低端口（远端端口低于 1024）也会换本机端口，后果第一条补上了
这个条件；地址写入是三个受控入口而不是两处；「两个地址分开说」目前只在接口里成立，界面还
没有渲染远端位置；自由 ssh 目标里的 `-S` 能覆盖启动器的 `ControlPath`，连接隔离因此有个
已知漏洞；托盘双击打开的失败只进日志。

## 追加（2026-11 注释清理）

- 退出时的撤销有 3 秒预算（tunnel.rs 的 EXIT_BUDGET）：撤销的每一条都是发给一条已建好连接的一句话，正常不花时间；预算只用来挡住一条不再应答的连接——宁可有几秒的转发残留，也不让退出卡在那里。
