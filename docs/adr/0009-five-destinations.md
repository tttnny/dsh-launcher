# 界面五个目的地：实例、安装、数据、机器、设置

## 背景

ADR-0004 把顶级导航收成三个目的地（实例、资源库、设置），把「准备实例要用什么」的三样资源
（版本、DSH_HOME、Profile）合进资源库。远程主机成为一等概念（ADR-0006）之后，这个分法开始
失真：

- 主机本来属于「资源」，可它的增删改测被放进了设置页。设置页因此混着两件事：启动器自身
  （外观、代理、更新、快捷键）与「哪台机器上有什么、怎么连」。想看某台机器，得先进设置。
- 资源库的三个标签页在一台机器上是三个目的地；远程主机让「当前主机」成了每次操作的前提，
  但「在哪台机器上装版本」「在哪台机器上建 DSH_HOME」并不比彼此更相近。
- 实例页按主机组织视图（全部主机 / 当前主机），侧栏一度又加了一组机器列表。同一件事在
  两个地方各说一遍，正是 ADR-0004 想结束的那种重复。

## 决策

**顶级导航按「用户要做什么」分五个目的地，一层，没有第二组机器列表。**

| 目的地 | 负责 | 不负责 |
| --- | --- | --- |
| 实例 | 启停、打开、编辑绑定、自检；实例详情里的插件与诊断 | 装版本、改 Profile、管机器 |
| 安装 | 每台机器上装了哪些版本、可装哪些、安装进度、设为终端里的 `dsh` | 运行实例 |
| 数据 | 每台机器的 DSH_HOME 与其中的 Profile（Profile 跟着 DSH_HOME 走，不单独成页） | 运行实例 |
| 机器 | 一条主机记录：身份、状态、连接测试、增删改测、环境检测入口、这台机器的足迹（实例、版本、DSH_HOME、数据目录） | DSH 自身的资源内容 |
| 设置 | 启动器自身：常规、外观、代理、更新、数据目录、快捷键 | 任何 DSH 资源 |

- 「当前主机」仍然只有一个，定义不变（ADR-0006 §3）：安装与数据按它显示；机器页是唯一修改
  主机记录的地方；实例页的「全部主机」是视图开关，不是另一台主机。
- 旧地址保留为重定向：`/library` 按 `?tab=versions` 分到安装或数据，`/versions`、`/tasks`
  到安装，`/homes`、`/profiles` 到数据，`/hosts` 到机器，`/setup` 到本机机器详情。
- 快捷键 ⌘1 实例、⌘2 安装、⌘3 数据、⌘4 机器、⌘, 设置；原生菜单与托盘仍走同一条
  `menu-navigate` 契约，入口与页面对应，旧载荷一并兼容。
- 页头标题只出现一次；工具栏是可拖拽的标题栏，不重复页面标题。

## 后果

- 设置页只讲启动器自己，不再出现「主机」「环境」两节；主机相关的事集中到机器页。
- 「资源库」这个词退出界面；版本与 DSH_HOME 各自成为顶级页，Profile 仍在 DSH_HOME 下面。
- 机器页成为主机记录的唯一写入口；实例详情里的主机栏只做高亮和跳转。
- 五个目的地都遵循同一条「当前主机」规则，不再有页面自己缓存「我在看哪台机器」。
- 插件页不再是一条与列表并列的独立入口：它从实例进入，在实例详情里展开（ADR-0001）。

## 备选方案

- **保留资源库，把主机也做成资源库的标签页**：被否。主机是「哪台机器」的选择前提，不是与
  版本、DSH_HOME 并列的资源；把它放进标签页会让「当前主机」与「选中的标签」互相争夺含义。
- **侧栏按主机分家**（ADR-0006 已否过一次）：被否。目的地的数量会按机器数翻倍。
- **给环境检测单独一个顶级导航**：被否。它回答的是「这台机器能不能跑 DSH」，属于机器，
  入口从机器卡片进入即可。

## 状态

本 ADR 取代 ADR-0004。ADR-0006 中「资源库的三个标签页」「主机的增删改在设置页」两处界面
细节随之失效；它关于主机归属、记录位置与删除语义的决策不变。
