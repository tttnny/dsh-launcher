# 顶级导航只留三个目的地

## 背景

侧栏曾有五项：首页 / HOME / Profile / 版本 / 设置。其中

- 首页（实例）与版本是每天都在用的；
- HOME 与 Profile 是「准备实例要用什么」的一次性配置；
- 设置是另一类东西。

五项等权重，于是每次要在两台机器间切 Profile，都要先判断「这个操作归哪一项」。
同一件事还被拆到两处做：实例卡上有 HOME 选择器，HOME 页有「查看 Profile」，
Profile 页又有 HOME 选择器 —— 三处都在改同一个绑定。

插件管理同样没有归属：它挂在 Profile 行上，但 `/plugins` 又是一条与列表并列的
路由，两侧各自维护「现在显示的是哪个 Profile」。

## 决策

**顶级导航按「用户要做什么」分三个目的地：实例 / 资源库 / 设置。**

| 目的地 | 负责 | 不负责 |
| --- | --- | --- |
| 实例 | 启停、打开、编辑绑定、自检 | 装版本、改 Profile |
| 资源库 | DSH 版本、DSH_HOME、Profile 三个标签页 | 运行任何东西 |
| 设置 | 启动器自身（外观、语言、代理、托盘、更新、数据目录、快捷键、环境） | DSH 的资源 |

- HOME 与 Profile 合并为资源库的两个标签页；标签页写在路由上
  （`#/library?tab=homes`），所以托盘与原生菜单仍能直达它们。
- 插件的入口只有一个：Profile 行上的「管理插件」。它是**独立页面**
  （`#/plugins?homeId=…&profile=…`），不再是「嵌在列表下方、把列表压暗」的区块。
- 实例卡不再提供 HOME 选择器：HOME 是绑定的一半，改绑只在实例详情页里发生。
- 页面标题只出现一次：工具栏不再重复页面标题（工具栏仍是可拖拽的标题栏）。

## 后果

- 旧链接全部继续可用：`/homes`、`/profiles`、`/versions`、`/plugins`、`/tasks` 都是
  重定向；托盘与菜单栏的 `menu-navigate` 载荷改指 `?tab=`，`/plugins` 仍是真页面。
- 快捷键重排为 ⌘1 实例、⌘2 资源库·DSH 版本、⌘3 DSH_HOME、⌘4 Profile、⌘, 设置。
  原生菜单同步改掉（不再用 ⌘H/⌘P，避免与「隐藏」「打印」撞键）。
- 视觉语言随之收敛：一条信号色（DSH 的蓝）只用于交互与状态，机器事实
  （版本号、端口、URL、路径、条目 id）一律用等宽字，颜色不再做装饰。

## 备选方案

- **保留五项，只做视觉整理**：被否。问题不在样式，在于「用什么」和「做什么」
  被放在同一层里。
- **把 HOME 与 Profile 也拆成顶级项**：被否。它们的使用频率与前两项差一个量级，
  并列会让高频操作更难找。
- **插件管理器继续嵌在 Profile 列表下**：被否。它需要整行宽度放条目表，嵌在列表
  下方只能靠「把上面压暗」来区分主次，那正是上一版的权宜之计。
