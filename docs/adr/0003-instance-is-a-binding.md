# 实例是一个绑定，不是一份数据

## 背景

安装一个版本会连带建一个 1:1 实例（`tasks::do_create_instance`，实例名固定为版本号）。
于是：

- README 承诺的「同一版本可建多个实例」做不到 —— 第二次安装同一个版本会报
  「同名实例已存在」；
- 界面里根本没有「新建实例」入口，`instances.newInstance` 这类文案一直是没有
  实现的死键；
- 也没有删除单个实例的能力：后端没有 `delete_instance`，唯一的删除路径是
  `remove_version`，它会连版本目录和专属 DSH_HOME 一起删掉 —— 想删掉一个实例，
  代价是删掉它所属版本的整份数据。

结果是实例只能越攒越多，而且不能改绑到别的 DSH_HOME 而不动版本。

## 决策

**实例是「版本 × DSH_HOME × Profile」的一条绑定记录，可以单独创建、单独删除。**

- `create_instance(name, version_id, home_id)`：只绑定已安装的版本；不安装、不建目录、
  不碰任何 DSH_HOME 的内容。同一台主机上同名拒绝——名字只在自己那台机器上需要不重名
  （`create_instance`、`update_instance` 与装版本的 `start_create_instance_task` 三处
  同一条规则），两台机器可以各有一个叫 `web` 的实例，所以行、托盘与插件链接都带上主机。
- `delete_instance(id)`：先停进程，再删记录，并清掉指向它的 `last_instance_id`。
  版本记录、DSH_HOME 记录与磁盘目录全部保留。
- 专属图标（`<HOME>/icons/<id>.png`，启动器自己写的那份文件）随实例一起删，
  这是实例唯一「自己的」磁盘产物。

## 后果

- 「同一版本多实例」「一个版本绑多个 HOME」都成为可达操作；「删除实例」不再需要
  牺牲版本。
- 实例的删除是**非破坏性**的：任何用户数据都在 DSH_HOME 里，而 DSH_HOME 不归实例。
  想删数据，走「删除版本」（ADR-0002 只管那条路径）。
- `instances.*` 那批描述「复制实例 / 删除实例」的文案里，删除终于落地；复制仍然没有
  实现，相应文案已删除。
- 例外的路径规则没有新增：本 ADR 不引入任何新的「可证明属于启动器」的目录，
  ADR-0002 的判定不变。

## 备选方案

- **让「安装」承担建实例的职责，靠改名绕开同名**：被否。安装的语义是装版本，
  多实例只是它的副作用；而且改名绕不开「想给同一个版本建第二个实例」这个需求。
- **删除实例时连带删除实例专属 DSH_HOME**：没有这样的目录（专属 HOME 按版本命名，
  见 ADR-0002），硬造一个就会破坏「一版本一目录」这条删除依据。
