# 一台主机的资源归它自己，顶级导航仍是三个

## 背景

启动器原本只管理一台机器——它自己所在的这台 Mac。版本是这台机器上的目录，DSH_HOME 是
这台机器上的目录，实例是这台机器上的进程。远程支持把这个默认打破了：同一份「版本 /
DSH_HOME / Profile / 实例」的清单要在多台机器上各有一份，而每份清单的内容只有那台机器
说得清——目录在它的文件系统上，进程在它的进程表里。

一个自然的诱惑是按机器分家：侧栏放几台机器，点进去各自有实例、版本、HOME、Profile。
那条路会把 ADR-0004 好不容易收成三个的目的地按机器数翻倍，并把「同一件事在两个地方
各说一遍」重新引回来。

## 决策

**主机是一等概念：一台主机带自己的一份版本、DSH_HOME、Profile 与实例清单，界面仍是三个目的地。**

1. 「主机」进数据模型：本机是内置的那一条（不可删），远程主机经 ssh 管理。每条版本、
   DSH_HOME 与实例记录都归某台主机。
2. 记录留在启动器本地（`config.json`，靠主机 id 归属）。远程主机上只有真东西——版本目录、
   DSH_HOME、日志、运行记录——没有一份会漂移的启动器配置副本（运行记录不算配置，
   见 ADR-0007）。
3. 界面不新增顶级导航。全局只有一个「当前主机」：资源库的三个标签页永远按它显示（装版本、
   建 DSH_HOME 必须指定一台机器，没有「全部」这一档）；实例页另有一个「全部」视图开关，
   勾上是所有主机的实例，关掉回到当前主机。
4. 主机的增删改在设置页；实例行上标主机名，托盘列出运行中的实例时也标。
5. 删除一条主机记录只删本地记录：不碰远端的目录，不停远端的实例，并且在删除前如实报出
   「远端留着什么、哪些实例会继续跑但启动器将看不到它们」，需要清理时给一条可复制的命令。
   这与 ADR-0003（删实例只删记录）和 ADR-0002（删版本才连专属 DSH_HOME 一起删）是同一个
   立场：启动器删的是自己知道的记录，不是别人的磁盘。
6. 远程主机只支持免密连接（密钥或 ssh-agent），启动器不保存任何密码或口令。它是图形程序，
   跑 ssh 时没有终端，密码无处输入，而把口令存进启动器的存储换不来多少东西。

## 后果

- 「版本」「专属 DSH_HOME」这些路径规则的基准从「启动器数据目录」变成「该主机的数据目录」
  （本机是 `~/Library/Application Support/in.dsh-plug.dsh-launcher`，远程主机上是那台机器上的
  `~/.local/share/dsh-launcher`，可覆盖）。覆盖值由**那台机器** settle 成绝对路径再记下来：`~`
  只有它展开得了，`..` / `//` / 末尾 `/` 也按文本归成一个，所以记录里存的是「测试连接」问回来的
  绝对路径；settle 不了的值（相对路径、`~用户名`）原样留在记录里并给出原因，而记录里还不是绝对
  路径的主机，拿不出数据目录来用——报错，不拿一个字面 `~` 去问那台机器。ADR-0002 的「两样一起删」
  在远程就是删那台机器上的目录、同时删本地那条记录。
- 主机记录里的 ssh 目标是自由字符串（可以是 `~/.ssh/config` 里的别名，也可以是
  `user@host -p 2222` 这类），直接交给系统 `ssh`；界面另从 `~/.ssh/config` 解析出别名列表让人
  挑。启动器不重新实现 ssh 的配置语言——免密、密钥、跳板、连接复用都写在用户自己的配置里。
- 远端环境探测沿用 ADR-0005 的三来源模型，但远程会跳过版本过低的 Node 候选（见该条追加）。
- 只在本地记事的代价：换一台 Mac 打开启动器就看不到这些远程记录。这是明知而受的——
  远端能查的东西（装了哪些版本、有没有进程在跑）都能从远端查回来，留在本地的只有「用户
  给它起了什么名字」这类书签性质的东西。
- 本机之外的主机，启动器不碰本机的文件系统：`Host::local_paths_only` 是那条规则。要在远端建
  或删就走传输层（`remote.rs` 里那些脚本）：建 DSH_HOME 由那台机器展开 `~`、按文本 settle
  `..`、把目录建出来并确认可写，拿回来的绝对路径才写进记录（`remote::ensure_home_path`，
  一句话一份脚本）；远端 DSH_HOME 的 Profile 读写、问出远端已有的 `~/.dsh` 也全部经那些脚本。
  `cleanup_orphan_homes` 只判本机：「这个目录不存在」这句话，本机的 `exists()` 只能对这台 Mac
  说。
- 一台机器上一个全新的 DSH_HOME 要先**在那台机器上**跑一次 DSH：`profiles/web` 是 DSH 第一次
  在一个 HOME 里运行时才建出来的，不先跑一次，那个 HOME 下一个 Profile 都选不出来，「启动」点了
  不会动。本机那份由安装任务补（`tasks::ensure_web_profile_template`），远端由
  `process::ensure_remote_web_profile_template` 做同一件事：起一次
  `node bin.js --profile web --host 127.0.0.1 --port 0`、等它打出 URL、按 pid 核对后停掉、把
  `profiles/web` 复制成 `profiles/__temp__`、再清掉复制件里那次启动钉住的端口。判据是「那个
  HOME 下一个 Profile 都没有」，不是「这是启动器建的 HOME」——已经有 Profile 的 HOME 一个字节
  都不碰。
- 远端安装的进度与日志读的是那台机器上的日志文件，等新输出的那一秒是在远端度过的（一次 ssh 顶
  一段输出，不是一秒一次）；脱离会话的命令没有 `wait` 可用，退出码由包装脚本写进同一份日志。
  取消要停那台机器上的**进程组**（`stop_pid` 只停组长，会留下占着 store 锁的子进程），并等
  那台机器确认进程真的没了才算「已取消」。

## 备选方案

- **不建主机概念，只在实例记录上多几个 ssh 字段**：被否。ssh 参数会在每条实例上重复，
  而且回答不了「这台机器上装了哪些版本」——版本与 DSH_HOME 天然属于机器。
- **顶级导航按主机分家**：被否，见背景。
- **远程也存一份启动器记录**：被否。多一份会漂移的副本，还要处理两边版本不一致时的迁移；
  换来的好处（多台 Mac 看到同一份记录）在只有一个启动器时不成立。
- **在 Rust 里内建一个 SSH 客户端库**：被否。见「后果」第二条。
