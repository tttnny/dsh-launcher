# 关窗与退出分离：窗口可以关掉再重建，退出才清理

## 背景

本机实例是启动器拉起的子进程，退出启动器就停掉它们（`process::kill_all`）。于是「关掉
窗口」和「退出应用」如果被 macOS 的默认行为当成一回事，用户关个窗就把所有实例停了。

反方向的坑同样真实：拦住「最后一个窗口关闭就退出」的那个 `ExitRequested`（`code` 为
`None`）能保住实例，但原生 Quit（Cmd+Q）产生的也是 `code: None`，会一起被拦掉——托盘
常驻就变成「退不出去」。

## 决策

**关窗、退出、实例是三套生命周期：关窗不退出，退出才清理。**

1. 关主窗口按设置「关闭主窗口时最小化到系统托盘」（`minimize_to_tray`）走两条路：开——
   `prevent_close` 之后隐藏窗口；关——窗口真的销毁。两条都不停实例、都不退出应用。
2. 应用活着，窗口就能重建：`windows::show_or_create_main` 在窗口不存在时新建一个；Dock
   图标的 `Reopen`、托盘与菜单里的「显示主窗口」都走这一条。
3. 只有显式退出才清理：应用菜单的「退出 DSH Launcher」与托盘「退出启动器」都是自定义菜单
   项（保留 Cmd+Q 加速键），走同一条路径——`process::kill_all` 之后 `app.exit(0)`。
4. 为什么不用原生 Quit：它的 `ExitRequested` 没有退出码，会被保活处理器
   （`api.prevent_exit()`）吃掉；自定义项给的是带退出码的退出，不拦。`RunEvent::Exit`
   里再兜一次 `kill_all` 与撤端口转发，任何退出途径都不会漏掉清理。

## 后果

- 窗口、应用、实例三个生命周期各自独立：窗口可关可建，应用常驻，实例只随显式退出结束
  （远端实例连显式退出也不停，见 ADR-0007）。
- 改菜单项或退出处理时要同时保住两条路：关窗不退出、退出必清理。少任何一条，代价是「关个
  窗把实例停了」或「点退出退不出去」。
- 重建出来的窗口要走同一段构建代码（`attach_close_behavior` 一起挂上），否则重建出来的
  窗口要么关不掉，要么关一下就退出。
- 设置页那句文案必须与实际一致：「关闭窗口后启动器仍在托盘运行，已启动的实例不受影响。」
- Dock 的 `Reopen`、托盘与菜单的「显示主窗口」都是重建入口，都只显示或重建窗口，不触发
  任何实例动作。

## 备选方案

- **关最后一个窗口就退出**：被否，见背景。
- **用原生 Quit，再在 `ExitRequested` 里判断是谁触发的**：被否。那个事件只带退出码，拿不到
  「用户从哪触发」；分不出来，就只能连 Cmd+Q 一起拦住。
