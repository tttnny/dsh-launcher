# 自更新只让界面提版本号，选包与校验都在后端

## 背景

启动器要能一键更新自己：下载本机平台的安装包，然后打开这个本机文件交给系统安装。这条能力
的危险不在下载，而在「打开本机文件」——它把远端内容变成一次本地执行。

界面那层网页是可变的。如果它提供下载 URL、哈希或落盘路径，一次注入或一条被改的状态就能
把安装包换掉，而启动器会照单全收。

## 决策

**前端只提交目标版本号；后端从固定的发布仓库选包、按发布信息校验、只打开校验通过的本机文件。**

1. 命令只收版本号（`download_launcher_update` 的 `version`），外加一个进度通道；URL、
   哈希、路径一律不接受。检查更新那条命令前端一个参数也不给：渠道由后端按当前版本的
   预发布标记自己定。
2. 发布信息来自固定仓库（`tttnny/dsh-launcher` 的 GitHub Releases，`RELEASES_API`）。
   后端自己挑包：按平台与架构找 `dsh-launcher_<版本>_<架构>.dmg`，universal 优先，并
   要求发布信息自带 `sha256:` 摘要、大小在合法区间内——缺一样就当这个发布没有安装包
   （`mac_installer`）。
3. 版本号自己再验一遍：能解析成 semver、严格高于当前版本、稳定版不升级到预发布；在发布
   列表里找同一个 tag，找不到就说「重新检查更新」。
4. 下载边下边算 SHA-256：收到超过声明大小立刻失败；收完大小或哈希对不上就删掉半成品，报
   「校验失败，请重新下载」。
5. 只有通过这些检查的文件才会被打开（`open::that`）；临时 `.part` 文件在每条失败路径
   上都删掉。

## 后果

- 扩展平台、改安装包命名或换缓存目录时，必须保留「后端选源 → 先验证 → 再打开」这个顺序。
  把其中任何一步挪到前端，这条边界就没了。
- 下载互斥（一次只准一个），进度按百分比回传；安装包落在启动器自己的缓存目录
  `launcher-update/` 下，不写用户可见的位置。
- 网络失败与校验失败是两种错误：前者给原始错误，后者明确说「重新下载」。
- 发布信息里没有摘要的旧发布会失去一键更新。这是有意的：没有哈希就说不清下载到的是不是
  那一条发布声明的东西。

## 备选方案

- **让前端传 URL 或哈希**：被否，见背景。
- **只靠 HTTPS，不校验内容**：被否。TLS 只说明「在和发布仓库说话」，说不出「这个文件就是
  那条发布声明的那个」；自更新打开的是安装包，这一步不能省。
