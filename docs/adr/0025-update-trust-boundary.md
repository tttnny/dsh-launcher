# 自更新由后端选包、验证签名并原位替换

## 背景

启动器下载新版本后，需要保留 macOS 已授予的权限，并在用户点击「重启」后进入新版本。macOS 按应用的代码签名身份识别授权。打开 DMG 让用户手动替换时，装上不同签名身份的应用可能需要重新授权。

## 决策

1. 界面只提交目标版本和进度通道。后端按当前版本决定检查渠道，从固定的 GitHub Releases 仓库 `tttnny/dsh-launcher` 选择高于当前版本的安装包。后端优先选 universal，再按本机架构选包。
2. 自动更新只选发布时标记为 `Signed macOS installer` 的 DMG。发布流程验证应用签名和 designated requirement 后才添加标签。下载时按 GitHub 提供的大小和 SHA-256 校验，成功后记录在后端，界面显示「重启」。
3. 点击「重启」时，后端重新校验 DMG，后台只读挂载，把新版应用复制到与当前应用同一卷上的临时目录。验证新版应用的版本、应用标识、可执行文件和代码签名，并要求它符合且保有当前安装的 designated requirement。
4. 校验完成后才原子交换新旧应用目录。当前启动器退出并清理后，从原安装路径启动新版，启动参数为空。
5. 下载状态由后端保留，重开主窗口时可直接恢复。临时安装错误保留「重启」，安装包缺失或校验失败时重新下载，签名身份不符时提供发布页面。

## 后果

- 具有同一 designated requirement 的更新保留 macOS 对应用身份的识别。未签名安装、签名身份迁移、没有签名标签的旧发布仍可通过发布页面手动安装。
- 界面没有指定下载 URL、哈希、文件路径或直接安装本机文件的接口。后端通过固定来源、大小、SHA-256 和应用签名共同验证安装包。
