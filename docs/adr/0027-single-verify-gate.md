# 合并前门禁只有 verify.sh 一个入口，测试套件按通配符发现

## 背景

合并前的检查原先散落在四处：开发文档里的几条命令、各处零散的步骤表、package.json 里一串 test:* 脚本，剩下的只活在人的记忆里。几份清单必然各自漂移，而漂移的代价是「没被接上的检查等于不存在」——一份漏了某步的清单，和没有这一步是一样的。

## 决策

**scripts/verify.sh 是合并前质量门禁的唯一入口，scripts/*.test.mjs 按通配符发现。**

1. 本地与 CI 都只跑它：pnpm verify 调 scripts/verify.sh，发版工作流的 Verify 一步也是 pnpm verify，没有第二份清单可抄。
2. 测试套件用通配符发现（SUITES=(scripts/*.test.mjs)），不写死名单：新增一个测试文件不该还要有人记得往清单里补一行——那种遗漏不会报错，只会让测试不再被跑到。
3. 任何一步失败立即以非零退出码结束，并说出是哪一步失败。--quick 只跑 clippy 与 Rust 测试，是「合并之间」的快速档，不代替完整门禁。

## 后果

- 新增检查的第一件事是加进 scripts/verify.sh；只加在文档、CI 或 package.json 里，就不会有人跑到它——这正是本决策要结束的那种漂移。
- 新增源码级测试放进 scripts/ 并命名 *.test.mjs 即自动接入，不需要在别处登记。
- 门禁依赖的工具（cargo 含 rustfmt 与 clippy 组件、node、pnpm 与仓库里的 prettier）由脚本在缺失时报出来；缺组件照着提示装，不用对照文档。
- 门禁的步数与顺序是为「合并前跑这一次」排的，不是可裁剪的选项清单；--quick 是唯一的短档。

## 备选方案

- **保留分散的命令清单**：被否，正是要结束的那种漂移，几份清单会继续各自漂移。
- **把测试文件列成固定名单**：被否。新文件靠人记得补一行，漏了就静默少跑，而且没有任何报错。
- **只靠 CI 把关**：被否，本地合并前无法复现 CI 的同一条命令，反馈只能等推上去。
