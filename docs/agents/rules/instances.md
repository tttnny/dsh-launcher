# 实例

管实例这条记录是什么、它的进程状态怎么变、实例行怎么排。术语见 `GLOSSARY.md`
（实例、绑定、运行记录），推理见 ADR-0003 与 ADR-0007。远端实例的启动、认领与停止
发生在跑它的那台机器上，这一份讲本机构造，跨机器的部分见 `hosts.md`。

## 实例是一条绑定记录

`create_instance` 只绑定已安装的版本，不建目录、不碰 DSH_HOME；`delete_instance` 只删
记录（加上实例自己的图标文件），版本与 DSH_HOME 一律留下——破坏性删除只属于「删除
版本」。「复制实例」是同一个命令加一个预填的弹窗，不要再加 `duplicate_instance`。

**实例名按主机唯一**：两台机器可以各有一个叫 `web` 的实例，判重只看同一台主机
（`create_instance`、`update_instance` 与装版本的 `start_create_instance_task` 三处
同一条规则）。

## 启动 token 要跨会话记住

实例就绪时打印的 URL（含 `token=`）写进 `<数据目录>/running.json`
（`process::remember_url`），实例停止 / 退出时删掉；收养外部进程前先用它验证。因此
「能不能管理插件」只由 `process::manageable_url`（URL 里有没有 token）决定，**不要**把
`adopted` 当拒绝理由——它只表示「停止时按 pid 杀」。只读横幅必须带一个能离开该状态的
按钮：没在跑给「启动」、有 token 在跑给「重启」、**主机不可达给「重试」**
（`refresh_instance_status`，与实例行同一条规则）——不可达绝不能给「启动」，那正是把
第二个 DSH 起到服务器上的那一下。

## 「主机不可达」是第五个状态，它不是「已停止」

`InstanceState::Unreachable` 表示「启动器现在没法知道这台机器上这个实例的状态」。加一个
状态值要**三处一起改**：`src/api/types.ts` 的联合、`home.status.*` 的 i18n 条目（中英
两份）、`src/styles/index.scss` 里 `.dl-status` 的 `is-*` 变体——少改一处这个状态就渲染
成别的东西，而「主机不可达」渲染成「已停止」会让用户去服务器上起第二个 DSH。**只有
「要离开表格」的终态才还要动第四处**：`src/stores/launcher.ts` 的 `applyStatus` 只认
`stopped` / `exited` 两个（它们要删掉那一行），其余状态一律原样透传，所以新加一个会被
推送的状态不必去 store 里找地方提它。前三处由 `ci/instance-state.test.mjs` 盯着。

启动时那一遍扫描还没问到的远端主机记在 `AppState.remote_scan` 里，
`process::list_statuses` 对它报 `starting`，**绝不报 `stopped`**；主机状态
（`AppState.host_statuses`）一旦是 `unreachable`，它的实例（包括本会话里已经认为在跑的
那些）就报 `unreachable`，页面给的是「重试」（`api.refreshInstanceStatus`），不是
「启动」。`delete_instance` / `remove_version` 先把停止的错误带出来再删记录。

## 启动时收养幸存进程

`process::adopt_surviving_instances` 在 app 启动后后台跑一遍——不认领的话，被替换 /
强杀留下的 DSH 进程会一直占着端口，界面就一直说「已停止」。认领依据：用户钉死的端口只要
有 DSH 样进程即可，随机端口必须先用 `running.json` 里的 token 认证成功才认。**这一遍
只看本机**：远端实例的端口在那台机器上，本机探它只会问到这台 Mac。

## 实例行是控制面，展开卡片只是事实

行本身讲的是「这台实例是什么、在不在跑」——名字、版本 / DSH_HOME、运行时的 URL、选
Profile、状态、主操作，行尾一个只作指示的展开箭头（点行或点实例名都展开，不是跳转）。
运行或启动中的实例，进程态动作（重启 / 停止 / 管理插件）也长在行上：它们排成控件区的
第二行，在主操作正下方（`.inst-tail` 竖排 + `.inst-tail-line` 横排、右对齐），这样
「打开 / 重启 / 停止」都是一次点击，而不是「先展开再点」——折叠是给读的，不是给按的；
这是用户明确嫌过的那次多余点击。`.inst-meta` 一行里，只有当实例属于**别的**主机、而且
界面同时在看多台机器（实例页的「全部」）时才多一个主机 chip：两台机器上的同名实例要分得
开，滤到某一台时不重复念同一个名字。

展开卡片里剩下的动作按「作用对象」分两段、各成一行：机器（终端 / 目录 / 日志）、绑定
（实例设置 / 复制实例 / 重新读取 Profile / 删除实例）。每段各自成行、段内才换行（`.facts-actions`
竖排 + `.facts-line` 横排）：都挤在一行时尾部的按钮会被宽度顶成孤立的一行。删除放在绑定
这一段末尾，与「实例设置」里的危险区是同一个 `delete_instance`、同一套确认文案——删的只是
这条记录，版本与 DSH_HOME 都留着。不要再引入
`⋯` 之类的 hover 菜单，也不要往行上塞图标按钮。机器那一段里，属于**别的**主机时「打开
目录」换成「复制路径」与「复制命令」两个按钮（仍然在这两段之内，段内换行）：那台机器上
的 DSH_HOME 打不开，能给的是路径与一条命令；终端与日志两个按钮不变，只是做的事在对面。
