# 注释审计规则

这里定义四类注释、动作映射、ADR 资格，以及清单、删除、校验的做法。

## 一、四个类别

1. 赘述（redundant）
   注释只是把代码里已经看得见的东西用自然语言重复一遍：重复字段名、类型、函数名、参数、
   显而易见的控制流；空注释；把签名翻译成一句话的文档注释；纯装饰的分节标题或横线。
   判据：删掉它，读者不丢失任何代码之外的信息。

2. 借口（excuse）
   注释的存在是为了让一个 hacky 实现显得合理，从而绕过真正的修复：承认妥协（「先这样」
   「暂时」「够用」「兜底」「权宜」「以后再说」「没有更好的办法」）、解释为什么不校验、
   不等待、不重试、硬编码、把已知缺陷留在注释里而不是 issue 里、没有链接的 TODO/FIXME。
   如果妥协已经被 ADR 或 issue 记录，注释本身只是指针，不算借口。

3. 过时（stale）
   注释描述的东西已经不存在、或与当前代码矛盾：引用了已删除的文件/目录/函数/命令/路由/
   环境变量，数量或顺序与代码不符，历史叙述（「曾经」「原来」「旧版」），ADR 引用指向
   不存在的编号或与 ADR 内容矛盾。核对方式见第四节。

4. 决策记录（decision）
   注释记录了代码本身看不出来的重要信息：为什么必须这样做、为什么不能那样做，
   顺序、所有权、信任边界、平台差异、数据归属、兼容性等约束。未来维护者不知道就会改坏。

## 二、类别到行动

| 类别 | 行动 |
| --- | --- |
| 赘述 | delete |
| 过时 | delete |
| 借口 | delete，并开 issue（见第五节） |
| 决策记录，已被现有 ADR 或 GLOSSARY 覆盖 | delete，报告里写 adrRef |
| 决策记录，达到 ADR 资格且未被覆盖 | 写进 ADR，然后 delete |
| 决策记录，局部实现约束，代码确实无法自明 | keep，进基线，留给后续轮次 |

keep 是例外，只用于「删掉会让未来的人踩坑、但又不值得写进 ADR」的约束。能用一句代码或
一个测试表达清楚的，delete。

## 三、ADR 资格

三条同时满足才算 ADR 级（来自 domain-modeling 技能）：

1. 难以逆转：以后改回去的代价明显。
2. 没有背景会困惑：未来维护者会问「为什么这样做」。
3. 真实权衡：有别的做法，且选择理由具体（平台事实、协议、数据安全、性能、兼容性等）。

局部的实现细节通常不满足第 2 条，归 keep 或删除，不要硬塞进 ADR。ADR 要克制：
宁可少写，也不要把 ADR 变成实现备注。格式按 .agents/skills/domain-modeling/ADR-FORMAT.md。

## 四、过时核验清单

- 提到的文件、目录、脚本：用 git ls-files 或 ls 确认存在。
- 提到的函数、类型、命令、参数、环境变量：用 grep 在仓库里确认。
- 提到的页面、路由、文案、快捷键：对照 src/router、src/shortcuts.ts、views。
- 提到的 ADR 编号：docs/adr/ 下现在有 0001-0008。
- 数量、顺序、默认值、平台条件：对照代码里的字面量。
- 历史叙述本身不是当前的决策理由，算过时。

如果发现 docs/adr 或 GLOSSARY.md 与当前代码矛盾，那是文档需要更新，不算注释的问题，
单独记下来并在本轮修文档。

## 五、借口要开 issue

每处 hacky 实现开一个 issue，写清楚：实现哪里 hacky、为什么是妥协、建议怎么修、
证据（文件与行号）。同一根因的多块注释合并成一个 issue。标题写实现问题，正文不复述注释。
按 AGENTS.md 的 issue tracker 约定操作（gh CLI，标签用 docs/agents/triage-labels.md 里的词）。

## 六、清单与合并

检查脚本输出的每一行注释是一个块。相邻的、各自独占一行的注释（中间没有空行、没有代码）
属于同一个语义块，审计时合并，报告 id 用块第一行的位置：文件路径:起始行号。
行尾注释单独成块，不跟下一行合并。

## 七、删除与校验

- 整行注释：连同所在行一起删除，包括行尾换行。
- 行尾注释：只删注释文本和它前面的空白，保留代码行。
- 块注释跨行：删除整个区间；删除后把连续的 3 行以上空行压到 1 行。
- 不重排代码，不增删代码。git diff 里只应有注释和空行变化。
- 校验顺序：node --test scripts/check-comments.test.mjs，然后 pnpm verify，最后检查
  node scripts/check-comments.mjs --report 的行数下降。

## 八、估算

--report 会给出每个文件的「含注释行数」与「纯注释行数」。纯注释行就是删掉后直接少掉的行；
再加上注释块前后的多余空行，就是一次完整清理的 LOC 收益。写报告时给出总数与百分比。

## 九、ratchet 的语义

- scripts/comment-baseline.json 按文件记录允许的注释行数。
- 新增注释使行数超过基线即失败；新文件默认 0 行。
- --update 只下调；--allow-increase 是显式例外，必须在 PR 说明理由。
- 目标是把基线清空，届时脚本成为硬禁止注释的检查。
